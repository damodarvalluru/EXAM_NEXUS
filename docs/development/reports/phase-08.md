### 2. OWASP ZAP baseline (passive scan)

A local ZAP baseline was executed from Docker Desktop while the compiled API was running. The
container targeted the host API through `host.docker.internal:3000`.

Command (API started separately with the repository `.env` loaded):

```powershell
docker run --rm -v "${PWD}:/zap/wrk:rw" -w /zap/wrk ghcr.io/zaproxy/zaproxy:stable `
  zap-baseline.py -t http://host.docker.internal:3000 `
  -c tests/security/zap-baseline.conf `
  -r evidence/phase-08/zap-baseline.html `
  -J evidence/phase-08/zap-baseline.json `
  -w evidence/phase-08/zap-baseline.md
```

Result: **exit code 2** (warnings only). Summary from the run: `FAIL-NEW: 0`, `WARN-NEW: 1`,
`PASS: 67`.

Triage:

- The only warning was informational alert **Storable and Cacheable Content [10049]** for
  `/robots.txt` and `/sitemap.xml`, both of which returned 404 during the crawl. ZAP assumed a
  liberal caching lifetime because no explicit directive was present on those responses. No
  high-, medium- or low-risk alert was reported.
- This is a passive baseline: it did not authenticate, did not test tenant isolation and did not
  send attack payloads. It is **not** a penetration test and does not satisfy the independent-review
  requirement.
- No finding was suppressed or edited in the raw report. Any future authenticated/tenant scan needs
  separate authorisation and credentials.

### 3. Semgrep source rules

The first local Semgrep run used the initial `secrets-written-to-logs` pattern with unconstrained
`$LOGGER` and `$LEVEL` metavariables. It reported **183 findings**, all from that one rule. Review
showed they were false positives: the unconstrained method pattern matched non-logging calls such as
`crypto.verify(secret, ...)`, webhook signing and password hashing, not secret values passed to a
logger. The raw initial SARIF is retained at
[`evidence/phase-08/semgrep-initial.sarif`](../../../evidence/phase-08/semgrep-initial.sarif).

The rule was corrected in `tests/security/semgrep.yml` to constrain `$LOGGER` to logger-like
receivers and `$LEVEL` to actual log levels. `semgrep scan --config tests/security/semgrep.yml --validate`
passed with 6 rules and 0 configuration errors.

The corrected local scan was then rerun with the original command:

```powershell
docker run --rm -v "${PWD}:/src" -w /src semgrep/semgrep:1.186.0 `
  semgrep scan --config tests/security/semgrep.yml --metrics=off `
  --sarif --output evidence/phase-08/semgrep.sarif .
```

Result: **Scan completed successfully; findings: 0; rules run: 6; targets scanned: 174;
exit code 0**. Semgrep reported that the scan was limited to files tracked by git; a further run
that explicitly includes untracked working-tree source was subsequently completed with 0 findings;
the raw result is retained at `evidence/phase-08/semgrep-untracked.sarif`.

Raw evidence:

- [`evidence/phase-08/semgrep.sarif`](../../../evidence/phase-08/semgrep.sarif)
- [`evidence/phase-08/semgrep.log`](../../../evidence/phase-08/semgrep.log)
